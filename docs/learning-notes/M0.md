# M0: Forge setup, learning notes

**Goal:** an empty but professional TypeScript CLI that builds, tests, lints and prints `heph --version`.

## What each file does

| File | Purpose | Concept to understand |
|------|---------|-----------------------|
| `package.json` | Name (`heph-cli`), `"type": "module"`, `"bin": { "heph": "dist/cli.js" }`, scripts | `bin` is how npm puts a command on your PATH. `"files"` controls what gets published (only `dist`, README and LICENSE). |
| `tsconfig.json` | Type checking only (`noEmit`); tsup does the actual build | `strict`, `noUncheckedIndexedAccess` (`arr[0]` may be `undefined`), `exactOptionalPropertyTypes`, `verbatimModuleSyntax` (forces `import type`) |
| `tsup.config.ts` | Bundles `src/cli/index.ts` into a single `dist/cli.js` with a `#!/usr/bin/env node` shebang | Bundling: dependencies stay external, and our code becomes one fast-loading file |
| `vitest.config.ts` | Test runner config | Tests live in `tests/`, mirroring `src/` |
| `eslint.config.js` | Lint rules, including a rule that **forbids `src/core/` from importing I/O or UI libraries** | The *Dependency Rule* from Clean Architecture, enforced automatically and not just by discipline |
| `.prettierrc.json`, `.editorconfig`, `.gitattributes` | Consistent formatting and LF line endings on every OS | Windows uses CRLF and Linux uses LF. Without this, CI on Linux would complain about files written on Windows. |
| `.github/workflows/ci.yml` | Runs every check on Windows, macOS and Linux with Node 20 and 22 | A matrix build catches "works on my machine" bugs such as path separators |
| `src/version.ts` | Reads `version` from package.json | A *named* JSON import lets the bundler inline just that one field |
| `src/cli/program.ts` | **Defines** the CLI (commands and options) | Separating *definition* from *execution* makes it testable in-process |
| `src/cli/index.ts` | **Runs** the CLI | A tiny entry point. Top-level `await` works because the project uses ESM. |

## Things worth noticing

1. **Why `createProgram()` instead of a global `program`?** Every test gets a fresh instance, so there's no shared state between tests. Later, `container.ts` will pass dependencies into it.
2. **`exitOverride()` in tests.** Commander normally calls `process.exit()`, which would kill Vitest. Overriding it turns the exit into an exception we can catch and inspect.
3. **The empty folders (`.gitkeep`)** are the architecture from the design doc §3. They exist now so the layers are visible from day one.
4. **npm 11 `allow-scripts` warning for esbuild.** Newer npm versions do not run package install scripts unless you approve them, which protects against supply-chain attacks. esbuild still works because its binary comes from an optional dependency. If a build ever complains, run `npm install-scripts approve esbuild`.

## Try it yourself

```powershell
npm run dev -- --help       # run from source, no build
npm run check               # typecheck + lint + format + tests (what CI runs)
npm run build; node dist/cli.js -v
```

**Exercise:** add a `--no-color` global option in `program.ts` and a test asserting it appears in `--help`. Then try importing `node:fs` inside a new file under `src/core/` and run `npm run lint` to watch the architecture rule catch it.
