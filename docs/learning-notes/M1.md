# M1: Talk to the oracle, learning notes

**Goal:** chat with an LLM from the terminal, with streamed answers, memory across turns, and switchable backends (LM Studio ⇄ OpenAI) through config only.

## The flow of one message

```
you type "hi"
  └─ TerminalUI.readLine()                       ui/        (only class touching stdin/stdout)
      └─ ChatRepl: slash command? no → agent      ui/
          └─ Agent.runTurn("hi", signal)          core/      (no I/O imports, enforced by ESLint)
              ├─ Conversation.addUser("hi")
              └─ provider.chat({model, messages})  ← LLMProvider INTERFACE
                   └─ OpenAICompatibleProvider     llm/       (the only file importing `openai`)
                        POST {baseURL}/chat/completions  stream: true
                        ← SSE chunks: "Hel", "lo", …, usage
              yields AgentEvents: text, text, …, turn_end
      └─ TerminalUI.render(event) → prints as it arrives
```

## Key ideas in the code

| Concept | Where | Why it matters |
|---|---|---|
| **The model has no memory** | `Agent.test.ts`, test "sends the whole history" | Every request re-sends the *entire* conversation. "Memory" is just us keeping a list. This is why long chats cost more tokens (watch `in` tokens grow in the footer: 214 → 247). |
| **Provider-neutral messages** | `core/conversation/Message.ts` + `llm/openai-compatible/mappers.ts` | The core never sees OpenAI types. A new backend means writing one new mapper. |
| **Streaming = async iteration** | `provider.chat()` returns `AsyncIterable<ChatChunk>`, `Agent.runTurn()` is an `async *` generator | Each layer transforms a stream: SSE → `ChatChunk` → `AgentEvent` → terminal text. No callbacks, easy to test. |
| **Cancellation with `AbortSignal`** | Ctrl+C → `TerminalUI` SIGINT → `ChatRepl` aborts the controller → SDK cancels the HTTP request | One signal flows through every layer. The partial answer is kept and marked `[interrupted by the user]`. |
| **Errors as data** | `LLMError` with a `kind` and a `hint` | The UI prints *what to do*. A failed turn is rolled back so the user can just retry. |
| **Config precedence** | `config/ConfigLoader.ts` | defaults < `~/.heph/config.json` < `./.heph/config.json` < env (`HEPH_PROFILE`, `HEPH_MODEL`, `HEPH_BASE_URL`) < flags |
| **Security: project config is restricted** | `ConfigLoader.test.ts` "SECURITY" test | A cloned repo could ship `.heph/config.json` pointing `baseURL` at its own server to steal your key. Project files may change `model`, but not `baseURL`, `apiKey` or `apiKeyEnv`. |
| **Composition root** | `src/container.ts` | The only place that calls `new` on concrete classes. Swap the UI or provider here and nowhere else. |
| **Lazy loading** | `src/cli/index.ts` dynamic `import()` | `heph --version` doesn't load the OpenAI SDK, so it starts in about 60 ms. |
| **Test doubles** | `ScriptedProvider`, `FakeTerminal`, a real tiny HTTP server in `OpenAICompatibleProvider.test.ts` | 47 tests run in under a second, offline. The live suite (`npm run test:llm`) checks real LM Studio behaviour. |

## Surprise found while testing
LM Studio **doesn't fail on an unknown model id**. It silently answers with the loaded model. Without a check, the banner would claim `does-not-exist` while qwen actually answered. Fix: `unlistedModelWarning()` compares the requested id against `/v1/models` at startup.

**Lesson:** "OpenAI-compatible" servers are *mostly* compatible. Live tests against the real server catch what mocks can't.

## Bug found by manual testing: pasting a file "loops forever"
**Symptom:** pasting a 50-line file into the chat made heph answer over and over.
**Cause:** readline emits one `line` event per newline. A paste is just text full of newlines, so it looked like **50 Enter presses**: 50 messages, 50 answers.
**Fix:** `ui/input/PasteAwareLineReader.ts`. After each line, wait a 30 ms "paste window". Lines that arrive inside it belong to the same message, because no human presses Enter twice in 30 ms. One subtle part: the `next()` call that loses the race against the timer must be **kept and reused**, or the next line you type would be silently lost (there's a test for exactly that).
Also: slash commands now only count on single-line input, so a paste starting with `/src/app.ts` is a message, not an unknown command.

**Lessons:**
1. Unit tests only check what you thought of. Real use finds the rest. That's why each milestone ends with "try it yourself".
2. Put tricky logic in a small class with no I/O (`PasteAwareLineReader` takes any `AsyncIterator<string>`), so you can test it with full control over timing.
3. Alternatives for later: terminal *bracketed paste mode* (`ESC[?2004h`), where the terminal marks the start and end of a paste exactly. It's more precise but not supported everywhere.

## Try it

```powershell
npm run dev                        # chat with LM Studio (profile "local", model "auto")
npm run dev -- models              # list models on the server
npm run dev -- -m qwen/qwen3-30b-a3b-2507
$env:OPENAI_API_KEY = "sk-..."; npm run dev -- -p openai
npm test                           # 47 offline tests
npm run test:llm                   # live tests (skipped if LM Studio is off)
```

Optional user config at `~/.heph/config.json` (Windows: `C:\Users\<you>\.heph\config.json`):

```json
{
  "defaultProfile": "local",
  "profiles": {
    "local": { "model": "qwen/qwen3-30b-a3b-2507", "temperature": 0.2 },
    "ollama": { "baseURL": "http://localhost:11434/v1", "apiKey": "ollama", "model": "llama3.1" }
  }
}
```

## Exercises
1. **Watch the tokens grow.** Chat for 5 turns and note the `in` tokens each time. Then `/clear` and compare. This is the problem M6 (context management) solves.
2. **Add `/history`**, which prints how many messages and roughly how many characters the conversation holds. Only add a file in `ui/slash-commands/` and register it in `BUILTIN_COMMANDS` (Open/Closed).
3. **Break the server on purpose.** Stop LM Studio's server mid-answer and see which error and hint you get.
4. **Read `mappers.ts`** and predict what must change when the model starts calling tools (M2).
