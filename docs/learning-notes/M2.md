# M2: Give it eyes (read-only tools + the agent loop), learning notes

**Goal:** heph can explore your project by itself, safely, and the terminal shows clearly what it is doing versus what it is saying.

## The agent loop (the heart of every coding agent)

```
❯ where is createProgram defined?
        │
        ▼
  ┌─────────────────────┐   tools: list_directory, read_file, glob, grep (JSON Schema)
  │ step 1: call model  │──────────────────────────────────────────────────────────►
  └─────────┬───────────┘   ◄── tool_call: grep {"pattern":"createProgram"}
            ▼
  ToolExecutor: look up → parse JSON → validate (zod) → [M3: permission] → execute → truncate
            │  result: "src/cli/program.ts:29: export function createProgram(…"
            ▼
  ┌─────────────────────┐   messages now include the tool call + its result
  │ step 2: call model  │──────────────────────────────────────────────────────────►
  └─────────┬───────────┘   ◄── text: "It's defined in src/cli/program.ts:29…"
            ▼
     no tool calls → turn over
```

The code is `core/agent/Agent.ts` (`runTurn`), about 100 lines. The rules it enforces:
1. **Every tool call gets a result**, even when cancelled, or the next API request is invalid.
2. **`maxSteps` (25)** stops a model that never stops calling tools.
3. **An error in any step rolls back the whole turn** (`conversation.truncate(mark)`).
4. Tools run **sequentially**. That's simpler and safer once tools can write (M3).

## How a tool works

| Piece | File | Role |
|---|---|---|
| `Tool` interface | `tools/Tool.ts` | name + description + zod schema + risk + `describe()` + `execute()` |
| zod → JSON Schema | `tools/ToolRegistry.ts` | `z.toJSONSchema(schema, { io: 'input' })`: one schema gives runtime validation **and** the model's documentation |
| `ToolExecutor` | `tools/ToolExecutor.ts` | the pipeline above. **Never throws**: errors become `"Error: …"` results that the model reads and corrects |
| `ToolRunner` port | `core/agent/ToolRunner.ts` | the Agent depends on this interface, not on `tools/` (DIP) |
| Streaming assembly | `llm/openai-compatible/mappers.ts` `ToolCallAssembler` | tool calls arrive in fragments (`{"pa` … `th":"a.ts"}`) keyed by `index` |

**The model only sees the description and the schema.** Look at `ReadFileTool.description`: "Always read a file before explaining… Never guess." Changing descriptions changes behaviour more than changing code does.

## File safety, layer 1 (always on, any mode)

| Threat | Defence | Test |
|---|---|---|
| `../secret.txt`, `src/../../x` | `PathGuard`: lexical check with `path.relative` | `PathGuard.test.ts` "BLOCKS escaping" |
| `C:\Windows\win.ini`, `/etc/passwd` | same lexical check | "BLOCKS absolute paths" |
| `project-evil/` next to `project/` | `relative()` check, not a naive `startsWith` | "BLOCKS a sibling folder…" |
| junction/symlink inside the project pointing out | `realpath` of the existing ancestor | "BLOCKS a symlink/junction" |
| `.env`, `*.pem`, `id_rsa`, `.git/` | `IgnoreRules.isSensitive`: read_file refuses, grep skips | `tools.test.ts` "SECURITY" |
| `glob "../**"` | pattern validation, plus `followSymbolicLinks: false` | "rejects patterns that climb out" |
| writing anything | **no write method exists** on `Workspace` (Interface Segregation) | M3 adds `WorkspaceWriter` + approval |

Verified live: asking Qwen to read `../outside.txt` produced `✗ read_file … Access denied … outside the workspace`.

## Clear output (`ui/render/`)

```
❯ where is createProgram defined?          ← you

● heph                                      ← the agent
  ✓ grep /createProgram/ · 6 matches · 23ms ← what it DID (spinner while running; ✗ = failed)

  It is defined in src/cli/program.ts…      ← what it SAYS (rendered Markdown)

  ── 5.5s · 2 steps · 5,839 in / 119 out tokens
```

- `TurnRenderer` handles event → text only (testable with a fake `write`). `TerminalUI` handles stdin/stdout only.
- **Markdown + streaming:** `MarkdownBlockBuffer` releases text in *complete blocks* (paragraph or closed code fence), each rendered once by `marked-terminal`. Answers appear block by block, not character by character. That's the price of formatting.
- The `Spinner` erases itself (`\r\x1b[2K`) and is disabled when output isn't a terminal.

## Surprises
- **Tokens grow fast with tools:** a simple question cost about 6,800 input tokens (system prompt + tool schemas + file contents, re-sent at every step). This is why M6 (context management) exists.
- **The model refused `.env` on its own** before calling any tool. Nice, but **never rely on the model for safety**. The tool blocks it regardless (unit-tested).
- **The model still hallucinates** (it invented a `--api-key` flag). Tools reduce guessing but don't eliminate it.
- The tool-call layer converted the escape `\uFEFF` (BOM) into the real invisible character while writing the file. The fix was `raw.charCodeAt(0) === 0xfeff`. Invisible characters in source are a real-world bug class.
