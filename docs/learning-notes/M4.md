# M4: Light the furnace (shell commands) + a livelier terminal, learning notes

**Goal:** heph can run your tests, builds and linters, always with your approval. The terminal makes it obvious who is speaking and what is happening.

## What happens when the model wants to run a command

```
model: run_command { command: "npm test", purpose: "Run the tests", cwd: ".", timeoutSeconds: 120 }
  │
  ▼ ToolExecutor
  preview → { kind: 'command', command, cwd (PathGuard-checked), warnings: detectDangers(command) }
  │
  ▼ PolicyPermissionGate (first match wins)
  read-only → DENY · deny rule → DENY · DANGEROUS → ALWAYS ASK
  allow rule (no ; && | > …) → ALLOW · "always" for this exact command → ALLOW · full-auto → ALLOW · else ASK
  │
  ▼ NodeShell (PowerShell on Windows, /bin/sh elsewhere)
  stdin closed · CI=1 · NO_COLOR · GIT_PAGER=cat · timeout → kill the whole process tree · Ctrl+C → kill
  live output → spinner label · ANSI stripped · huge output keeps head + tail
  │
  ▼ result to the model: "$ npm test\nexit code 1 · 3.2s\n\n<output>"   (exit ≠ 0 → ✗ in the UI)
```

## Key ideas

| Concept | Where | Why |
|---|---|---|
| `Shell` port | `shell/Shell.ts`, `shell/NodeShell.ts` | tests use a `FakeShell`, so no process ever starts in unit tests of the tool |
| PowerShell `-EncodedCommand` | `NodeShell.#spawn` | base64 UTF-16 means **zero quoting bugs**. The wrapper forces UTF-8 and returns the real `$LASTEXITCODE` |
| Kill the TREE | `killTree` (`taskkill /T`, `kill(-pid)`) | `npm test` → node → vitest workers: killing only the first leaves orphans running |
| Non-interactive | `CI=1`, `stdin: ignore` | without it, `vitest` enters watch mode and the agent waits forever |
| Danger detector | `tools/shell/DangerousCommandDetector.ts` | a match never blocks. It forces a question (even in full-auto) and paints a red DANGER band |
| Allow/deny rules | `permissions/PermissionRules.ts` | `"run_command:npm test"`, wildcard `*`. **Allow rules never match chained commands** (`npm test && curl … \| sh`) |
| "always" = exact command | `grantScope()` | "always allow commands" would be far too broad. Dangerous commands are never remembered |
| Project config | `ConfigLoader` | a project may ADD deny rules but its allow rules are ignored (with a warning) |

## The new terminal look (`ui/render/theme.ts`)

```
╭─ ask · qwen3 · Enter send · Tab complete · ↑↓ history · /help     ← input box (while typing)
╰─❯ run the tests and fix the bug

 ❯ run the tests and fix the bug                                    ← becomes a SLATE bubble (you)
 ● heph                                                             ← ORANGE badge (agent's turn)
   ✓ read_file math.js · 1 lines · 1ms                              ← DARK band (what it DID)
  ╭─ edit_file · math.js · +1 −1
  │ 1 - exports.add = (a, b) => a - b;                              ← RED band
  │ 1 + exports.add = (a, b) => a + b;                              ← GREEN band
  ╰─
  ⚑ heph needs your approval                                        ← AMBER band (red if dangerous)
  Apply this change? y yes · a always for edit_file · n no · f …
▎ I fixed the bug…                                                  ← ORANGE bar (what it SAYS)
```

- **Bubble trick:** after Enter, the cursor moves up over the echoed input (`ESC[nA`), clears (`ESC[0J`) and redraws the message as a coloured band. The row count is computed from the text length and terminal width.
- **Hammer animation** (`HammerSpinner.ts`): 3 rows redrawn in place (`ESC[2A` = up 2 rows). It falls back to a one-line spinner on narrow or non-terminals, or with `HEPH_SPINNER=simple`.
- **Tab completion** is readline's `completer`. **↑/↓ history** is readline's built-in `historySize`.
- Backgrounds only appear when the terminal supports colour (`chalk.level >= 2`). Tests run with the plain theme.

## Bugs found while testing
1. **`cat ~/.ssh/id_rsa` was NOT flagged as dangerous.** The regex ended with `\b`, but there is no word boundary between `~` and `/` (both are non-word characters). The fix was a lookahead `(?=[\\/\s]|$)`. **Lesson:** write "must flag" *and* "must not flag" test tables for every security regex.
2. **"Staircase" output in the screen test.** That was the emulator, not heph: real terminals turn `\n` into "new line + column 0" (`onlcr`), and the headless emulator needed `convertEol: true`.
3. **Tab completion "didn't work" in an automated test.** The test sent `/mo` and Tab in one chunk, and Node's readline treats multi-character chunks as a **paste** and disables completion on purpose. Typed key by key, it works.

## Verified with the real model (simulated terminal + headless xterm)
"Run the tests, find the bug, fix it, and run the tests again." heph read `test.js` and `math.js`, proposed the `-` → `+` diff (approved), ran `node test.js` in PowerShell (approved, exit 0), and summarised honestly.


### Bug found: the spinner erased the model's reasoning
qwen3.8 streams its reasoning *before* calling a tool. The renderer printed it but left the cursor mid-line. The spinner then started on that same line, and its `\r` + "erase line" wiped the reasoning. All that remained was two mysterious blank lines.

How it was found:
1. The screen render showed blank lines.
2. Replaying events in the renderer alone did not reproduce them, so something else was involved.
3. The raw bytes showed newlines right after the spinner frames.
4. Logging the real agent events revealed reasoning arriving before the tool call.

Fix: `#spin()` always ends the current line before starting the spinner. There is a regression test.
**Lesson:** when two components share one terminal line, decide explicitly who owns the cursor.
