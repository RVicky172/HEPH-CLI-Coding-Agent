# M3: Give it hands, with permission (learning notes)

**Goal:** heph can change files, but **only with your approval**, with a diff shown first and `/undo` always available.

## What happens when the model wants to edit a file

```
model: edit_file {path, oldText, newText}
  │
  ▼ ToolExecutor
  1-3. look up · parse JSON · validate (zod)
  4a. tool.preview()  ──► WorkspaceWriter.load(): inside workspace? not a secret? not .git/.heph?
  │                       read before? unchanged since read? oldText found exactly once?
  │                       any failure → error to the model, the user is NOT bothered
  4b. PermissionGate.check(diff)
  │      read-only → DENY · "always" granted → ALLOW+show · auto-edit → ALLOW+show · ask → Approver
  │                                                                                     │
  │      ╭─ edit_file · src/math.ts · +4 −0                                              │
  │      │ 5 + export function times(a: number, b: number) {        ◄────────────────────┘
  │      ╰─
  │      Apply this change? y yes · a always · n no · f no, with feedback ›
  │
  5. execute → WorkspaceWriter.write(): re-check everything → checkpoint → write
  6. result to the model: "Edited src/math.ts …"   or   "NOT APPLIED: the user rejected …"
```

## Where each idea lives

| Concept | File | Key point |
|---|---|---|
| Permission modes | `permissions/PermissionMode.ts` | `read-only` < `ask` < `auto-edit` < `full-auto` |
| Decision logic | `permissions/PolicyPermissionGate.ts` | first match wins: read → mode → session grant → auto → ask |
| Asking a human | `permissions/Approver.ts`, implemented by `ui/TerminalUI.ts` | Ctrl+C or no terminal = **deny**. Never hang, never assume yes |
| Safe default | `denyAllChangesGate` | forgetting to wire a gate can never mean "allow everything" |
| Write access (ISP) | `workspace/WorkspaceWriter.ts` | only write tools get it (constructor injection). Read tools *can't* write |
| No blind/stale edits | `workspace/FileReadTracker.ts` | must `read_file` first. If the file's mtime changed since, read again |
| Exact-snippet edits | `tools/fs/EditFileTool.ts` | unique match required, CRLF preserved, `$&` inserted literally, helpful "not found" hints |
| Diff preview | `tools/fs/diffPreview.ts` → `ui/render/DiffRenderer.ts` | library-neutral `ActionPreview`, so the UI doesn't depend on the `diff` package |
| Undo | `workspace/CheckpointStore.ts`, `/undo` | restores the bytes, or deletes a file heph created. The model gets a note |
| Notes to the model | `Agent.addNote()` | after `/undo` or `/mode`, the model would otherwise assume old facts |
| Project can't loosen | `ConfigLoader` `stripLooserMode` | a cloned repo can make heph stricter, never switch you to full-auto |

## The guarantee, proven by tests (`writeTools.test.ts`, `PolicyPermissionGate.test.ts`)
- `ask` + "no" → file unchanged · new file not created · model told "NOT APPLIED"
- `read-only` → refused **without** asking
- `.env`, `.git/…`, `.heph/…`, `../outside.txt` → blocked **even in full-auto, before asking**
- an edit without a prior read → refused, the user isn't bothered
- the file changed after reading → refused (protects your unsaved work)
- live (`npm run test:llm`): the real model edits after "allow" and the file is byte-identical after "deny"

## Bugs and surprises found by testing with the real model
1. **The model lied about success.** With no terminal to approve, it said "I've added a multiply function" while the file was unchanged. The fix had two parts:
   - denial messages now start with **`NOT APPLIED: … nothing was changed`**
   - the system prompt has a **HONESTY** rule: a change happened only if the tool result says so.

   **Lesson:** an agent's summary is not evidence. Tool results are. Design the *messages* to the model as carefully as the code.
2. **Self-recovery works.** After feedback ("call it `times`"), the model's first edit failed (`oldText not found`). It read the hint, re-read the file, and succeeded. Good error messages *are* the retry strategy.
3. **Escapes inside generated code.** Patch scripts using template literals turned `\n` and `\[` into real characters, twice. Lesson: when code contains escapes, edit it with a tool that doesn't interpret them.

## Try it
```powershell
npm run dev -- -C D:\path\to\a\test\project     # default: ask mode
npm run dev -- -C D:\path\to\a\test\project --mode auto-edit
```
In chat: "add a function …", answer `f` with feedback, then `y`, then `/undo`. Also try `/mode read-only` and ask for an edit.

## Exercises
1. Add a `delete_file` tool (risk `write`, preview = "the whole file becomes −N lines", checkpoint so `/undo` brings it back).
2. Show `/undo` history: add a `/changes` command listing the checkpoints of this session.
3. Persist checkpoints in `.heph/checkpoints/` so undo survives a restart (and write a `.heph/.gitignore` with `*`).
4. Make the approval prompt single-keypress (raw mode) instead of letter + Enter. What gets harder?
